# Обновление «Сербского лета» из Codex и Claude Code

GitHub `peregond/SerbianSummer` — основной источник кода. Публичная игра работает в **существующем** проекте Sites `appgprj_6adca02988388191880eec9302e53338` по адресу https://serbskoe-leto.peregon.chatgpt.site/. В проекте привязана действующая база D1 с binding `DB`. GitHub push не публикует сайт автоматически.

## Обычный цикл работы

1. Начните с актуального `main`. Прочитайте `AGENTS.md`, `PROJECT.md` и этот файл. Проверьте `git status`; сохраните чужие незакоммиченные изменения. Создайте отдельную ветку `codex/...` или тематическую ветку Claude.
2. Внесите изменение. Сохраняйте ID сцен, `STORY_VERSION`, формат сохранений и базу игроков, если задача явно не требует другого. Для игровых файлов обновите `APP_VERSION` в `public/release.js`, затем `npm run stamp`; отдельно проверьте версию английского словаря, если менялся `public/locales/en.json`.
3. Выполните `npm run lint`, `node --test tests/*.test.mjs`, `npm run build`. Исправьте ошибки. Предупреждения перечислите в отчёте.
4. Отправьте ветку в GitHub, проверьте CI, объедините с `main` без принудительного push. Запомните полный SHA итогового `main`.
5. Перед публикацией прочитайте текущий источник **этого же** проекта Sites и сравните его с итоговым `main`. Если в Sites есть более новые изменения, сначала перенесите их в GitHub и повторите проверки. Не затирайте их только потому, что истории Git не связаны.
6. Используйте штатный инструмент Sites для сборки/упаковки исходников и production-публикации в `appgprj_6adca02988388191880eec9302e53338`. Сохраните домен, публичный доступ, настройки, секреты и binding `DB`. Не создавайте новый проект и не заменяйте production D1 локальной базой. Миграции запускайте только по отдельной задаче после проверки.
7. Откройте публичный адрес и проверьте фактическую версию, главные переходы на телефоне, RU/EN, загрузку изображений и музыки. Для изменений сохранений/аккаунтов дополнительно проверьте продолжение игры. Сообщите GitHub SHA, опубликованный Sites SHA и URL. Если публикация недоступна, назовите препятствие и не выдавайте push или локальную сборку за релиз.

## Где запускать публикацию

Codex с подключённым Sites может выполнить шаги 5–7 в той же задаче. Claude Code может подготовить код, тесты, ветку и PR; production-публикация из Claude возможна только при наличии у его среды **авторизованного доступа к Sites**. Если такого доступа нет, передайте итоговый SHA в Codex с Sites и попросите опубликовать существующий проект. Ключи Sites и базы не добавляйте в репозиторий или чат.
