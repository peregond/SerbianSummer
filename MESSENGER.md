# Экран переписки

Переписка — переиспользуемый HTML/CSS-шаблон, без изображений интерфейса и без отдельного хранилища сообщений. Все существующие страницы с `message: true` открываются на весь экран. Девять старых письменных ответов, оформленных как обычные реплики игрока, подключены через `CHAT_SCENES` в `public/messenger-config.js`.

## Настройка

- `public/messenger-config.js`: общий акцентный цвет, название канала, предел видимой ленты, настройки старых сцен.
- `public/messenger.css`: пузыри, шапка, черновик, кнопки, мобильная геометрия и тёмная тема.
- `public/messenger-model.js`: выбор собеседника, направления и уже доступных сообщений.
- `public/messenger.js`: DOM-шаблон. Не меняет сюжет или сохранения; вызывает переданные обработчики.

Входящее сообщение в новой сцене:

```js
{ speaker: 'milica', text: '«Привет, ты уже дома?»', message: true }
```

Исходящий текст, который игрок отправляет кнопкой:

```js
{
  speaker: 'player', text: '«Да, только что добрался{a}»', message: true,
  chat: { direction: 'outgoing', contact: 'milica' }
}
```

`chat.contact` принимает имя или существующий идентификатор (`milica`, `nikola`, `host`, `contact`, `districtHost` и т. д.). `host` и `contact` зависят от уже выбранных флагов. `node.chat.contact` задаёт собеседника по умолчанию для сцены, `page.chat` — настройку конкретной страницы, `page.chat = false` оставляет её в обычном проигрывателе. Учитывай общие инструкции PROJECT.md: не вставляй страницы и не переставляй старые реплики ради оформления.

Когда текущая страница заканчивается сюжетным выбором либо телефонным действием `kind: 'reply'`, шаблон предлагает существующие варианты. Выбор сначала заполняет неизменяемый черновик; только «Отправить» применяет исходные эффекты и переход. Если подпись варианта описывает намерение, а для пузыря нужен точный текст сообщения, добавь к варианту `chatText`: это меняет только отображение, не каноническую запись выбора. Любой новый русский текст, включая `chatText`, должен иметь перевод в `public/locales/en.json`.

После успешной отправки виден исходящий пузырь и кнопка «Продолжить историю». К этому моменту следующий сюжетный шаг уже сохранён; кнопка только показывает его. Повторная отправка заблокирована. Перезагрузка продолжает сохранённый шаг, а не отправляет сообщение второй раз. «Назад» использует существующий возврат и отменяет последствия выбора.

Лента содержит уже открытые сообщения текущей сцены с одним собеседником. Будущие реплики и сообщения других контактов не показываются. Рассказанные мысли выводятся отдельно от пузырей. Обычные действия (например, осмотр квартиры) остаются в игровом проигрывателе после кнопки «К действию».

Формат сохранения остаётся 1; `node`, `index`, эффекты, точки глав и предел возврата не меняются. История по-прежнему хранится в каноническом русском виде. Экран поддерживает RU/EN, safe area, масштаб текста, тёмную тему и уменьшение анимации.

## Проверка

`node --test tests/*.test.mjs`, `npm run lint`, `npm run build`.

Ручные сценарии: исходящее сообщение `prepare_host:0`; входящее `prepare_host:1`; ответ выбранному персонажу `evening_contact_plan:2`; варианты телефонного действия на последней странице `last_message`; переход к осмотру квартиры `district_dorcol:4`. Проверь отправку, повторное нажатие, возврат, перезагрузку и английский язык. Изолированные тестовые сохранения не должны заменять пользовательский прогресс.

Оформление повторяет предоставленный референс Viber: стеклянная светлая шапка, аватар, контурный фон, белые и фиолетовые пузыри, двойные галочки и нижняя капсула ввода. Варианты раскрываются через «Варианты ответов»; продолжение — круглая стрелка. Меню и настройки находятся под стрелкой рядом с именем. Иконки звонков и вложений декоративные, без доступа к камере и микрофону. Аватары задаёт `MESSENGER_CONFIG.avatars`; `page.chat.time` и `page.chat.quote = { author, text }` добавляют время и цитату.
